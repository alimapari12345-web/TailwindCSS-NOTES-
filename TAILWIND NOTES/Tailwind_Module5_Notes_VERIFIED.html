1Grid Container

Adding grid to an element turns it into a grid container. Unlike flex, applying grid alone does not automatically arrange children into a visible layout, a column structure still needs to be defined.

<div class="grid grid-cols-3 gap-4">
  <div class="bg-sky-500 p-4">One</div>
  <div class="bg-sky-500 p-4">Two</div>
  <div class="bg-sky-500 p-4">Three</div>
</div>
Key difference from flex: flex by itself produces a working row layout. grid by itself produces a single column of stacked, full-width children, since no column count has been defined yet. grid-cols-* is what actually creates the visible grid structure.

2Defining Columns

grid-cols-{n} splits the container into n equal-width columns. Every direct child is placed into the next available cell, left to right, top to bottom, automatically.

ClassEffect
grid-cols-2Two equal-width columns
grid-cols-3Three equal-width columns
grid-cols-4Four equal-width columns
grid-cols-12Twelve columns, commonly used as a flexible base grid for custom layouts

Children wrap automatically onto a new row once three columns are filled

Unlike flex, there is no manual wrap class needed for this row-to-row behavior. It happens automatically as soon as a column count is set and there are more children than columns.

3Spanning Columns

A single child can be made to occupy more than one column using col-span-{n}, applied to that child, not the container.

ClassEffect
col-span-2This item stretches across 2 columns instead of 1
col-span-fullThis item stretches across every column in the row
<div class="grid grid-cols-3 gap-4">
  <div class="col-span-2 bg-emerald-500 p-4">Wide</div>
  <div class="bg-sky-500 p-4">Normal</div>
</div>

Key point: the span number cannot exceed the total column count of the container. A col-span-4 inside a grid-cols-3 container will not overflow visually, it gets constrained to the available columns, but it defeats the intended layout, so span values should always be checked against the container's column count.
Good to know (not required at this stage): a newer utility, grid-cols-subgrid, lets a nested grid inherit the exact column tracks of its parent grid instead of defining its own. This is useful for keeping deeply nested grid items aligned to an outer grid, but it is an advanced case and not something a beginner project needs yet. It is mentioned here only so the term is recognized if seen in other code.

4Gap in Grid

gap-* works identically in grid as it does in flex, using the same spacing scale from Module 3. It adds space between cells, both horizontally and vertically, without adding space around the outer edge of the container.

ClassEffect
gap-4Equal spacing between rows and columns
gap-x-4Horizontal spacing only, between columns
gap-y-4Vertical spacing only, between rows

5Grid vs Flex — When to Use Which

Both create layouts, but they solve different problems. The core distinction: flex arranges items along a single line (row or column) and lets content decide sizing. Grid arranges items into a defined two-dimensional structure of rows and columns, decided upfront.

SituationBetter fit
A navbar with logo, links, and a button in one rowFlex
A photo gallery of evenly-sized tilesGrid
A single row of buttons that should space out evenlyFlex
A dashboard layout with a sidebar and a main content area of defined proportionsGrid
Centering one item inside a boxFlex
A pricing table with three equal-width plan cardsGrid
Rule of thumb: if the layout is fundamentally a single row or single column of items, reach for flex first. If the layout needs to be thought of as a grid, rows and columns together, reach for grid.

?Common Questions & Misconceptions

MythAdding grid alone arranges children automatically, the same way flex does.
Incorrect. flex alone produces a working row layout. grid alone produces a single stacked column, since no column count has been defined. grid-cols-* is required to see the actual grid structure.
Q&ADo grid children need a wrap class to move to a new row?
No. Once a column count is set with grid-cols-*, extra children automatically flow onto new rows. This is different from flex, where flex-wrap must be added explicitly.
Mythcol-span-* is applied to the grid container.
It is applied to the individual child that should stretch across multiple columns, not to the container itself. The container only needs grid and grid-cols-*.
Q&AWhat happens if col-span-4 is used inside a grid-cols-3 container?
The span value gets constrained by the available columns rather than overflowing visibly, but the intended layout is not achieved as written. Span values should always stay within the container's defined column count.
MythGrid and flex are interchangeable, pick whichever is familiar.
They solve different structural problems. Flex is one-dimensional, a single row or column. Grid is two-dimensional, rows and columns together, defined upfront. Using flex to fake a grid or grid to fake a simple row both lead to unnecessary extra classes.

✓Summary

  • grid creates a grid container, but needs grid-cols-* to actually define columns.
  • Children automatically flow into the next cell and wrap onto new rows, no wrap class required.
  • col-span-{n} is applied to a child, making it stretch across multiple columns.
  • gap-* spaces cells apart using the same spacing scale as Module 3, without adding space at the container's edge.
  • Flex suits single-row or single-column layouts. Grid suits layouts that need rows and columns defined together.
