1Padding

Padding is the space inside an element, between its border and its content. Tailwind controls it with the p- prefix and its directional variants.

ClassEffect
p-4Padding on all four sides
px-4Padding left + right only
py-4Padding top + bottom only
pt-4 / pr-4 / pb-4 / pl-4Padding on a single side (top/right/bottom/left)
<div class="p-6 bg-slate-800">
  Content with padding on all sides
</div>

<div class="px-8 py-3 bg-slate-800">
  Wider horizontal padding, shorter vertical padding
</div>

The number after the prefix is not a pixel value. It refers to a step on Tailwind's spacing scale, covered in Section 3.

2Margin

Margin is the space outside an element, between its border and neighboring elements. It follows the exact same naming pattern as padding, using m- instead of p-.

ClassEffect
m-4Margin on all four sides
mx-4Margin left + right only
my-4Margin top + bottom only
mt-4 / mr-4 / mb-4 / ml-4Margin on a single side
mx-autoAutomatically centers a block element horizontally (requires a set width)

Negative margins

Prefix the class with a dash to pull an element in the opposite direction of normal margin.

<div class="-mt-4">
  Pulled 4 spacing-units upward, overlapping the element above it
</div>
Note: mx-auto only centers an element if it already has a fixed or max width. Without a width, there is nothing for "auto" to center within, and the class has no visible effect.

3The Spacing Scale

Tailwind's spacing scale is used by padding, margin, width, height, and gap. The number in a class is a step on this scale, not a literal pixel count. Each step equals 0.25rem (4px at the default browser font size).

Steprempx
10.25rem4px
20.5rem8px
41rem16px
61.5rem24px
82rem32px
123rem48px
164rem64px

Formula: step × 4px = pixel value (at default settings). Step 4 is 16px, step 8 is 32px, and so on.

Key point: This is a fixed, shared scale across the entire framework. Learning it once for padding means it already applies to margin, width, height, and gap without relearning anything.

4Width & Height

Width and height also use the same numeric spacing scale, plus a set of keyword values for common cases.

ClassEffect
w-4 / h-4Width/height using the spacing scale (16px)
w-64 / h-6416rem (256px)
w-full100% of the parent element's width
w-screen100% of the viewport width (ignores parent size)
min-w-0 / max-w-mdMinimum/maximum width constraints

w-full vs w-screen

  • w-full fills the width of whatever contains it. If the parent is 400px wide, the element becomes 400px wide.
  • w-screen always fills the entire browser viewport width, regardless of the parent's size. This can cause horizontal overflow if the element sits inside a padded or centered container.
Common error: using w-screen inside a page that already has side padding. This makes the element wider than its container and creates an unwanted horizontal scrollbar.

5Borders & Radius

Border width and color

ClassEffect
border1px border, all sides, default color
border-2 / border-4Thicker border widths
border-{color}-{shade}Sets border color, e.g. border-sky-500
border-t / border-bBorder on a single side only
Order matters for visibility: a border class alone (border) does not show a border width unless paired with a border style. By default it renders as a solid 1px line, but if border-{color} is added without the base border class, no border appears at all, since there is no width set yet.

Border radius

ClassEffect
roundedSmall default radius on all corners
rounded-lg / rounded-xlLarger radius steps
rounded-fullFully circular/pill shape (50% radius)
rounded-t-lgRadius applied to top corners only

6Arbitrary Values

The spacing scale does not cover every possible number. Arbitrary value syntax allows any exact CSS value using square brackets.

<div class="w-[350px] h-[220px]">
  Exact pixel dimensions not on the default scale
</div>

<div class="top-[13px] text-[15px]">
  Works for most properties, not only spacing
</div>
  1. The value inside the brackets is written exactly as it would be in plain CSS: px, rem, %, vh, etc.
  2. No spaces are allowed inside the brackets. Use an underscore if a value requires a space, such as in some CSS functions.
  3. Arbitrary values work across most utilities, including colors: bg-[#1e3a8a] is valid.
When to use this: arbitrary values are meant for exceptions, matching a specific design spec, or a one-off measurement. Relying on them for most of a layout usually signals that the project should extend the theme in tailwind.config.js instead (covered in Module 9).

?Common Questions & Misconceptions

MythThe number in p-4 means 4 pixels.
Incorrect. It is step 4 on the spacing scale, which equals 1rem (16px) by default. The class name and the pixel value are not the same number.
Q&AWhy does mx-auto sometimes do nothing?
It requires the element to already have a defined width (a fixed value or a max-width class). Without a width, there is no extra space on either side to distribute, so centering has nothing to act on.
Mythw-screen and w-full behave the same way.
They do not. w-full is relative to the parent container. w-screen is relative to the entire browser viewport and ignores the parent, which can cause layout overflow inside padded containers.
Q&AWhy doesn't border-red-500 show a border on its own?
A color class only sets the color of a border, not its width. Without the base border class (or a width variant like border-2), the border width remains zero, so no border is visible regardless of color.
Q&AAre arbitrary values considered bad practice?
Not inherently. They are appropriate for one-off, exact requirements. They become a problem only when overused as a substitute for learning or extending the standard scale, since that reduces consistency across a project.
MythEvery utility property has its own separate numbering scale.
Padding, margin, width, height, and gap all share the same spacing scale. Learning the scale once applies to all of them.

✓Summary

  • Padding (p-) is space inside an element; margin (m-) is space outside it.
  • Both use directional variants: x for left/right, y for top/bottom, or a single side letter.
  • The spacing scale is shared across padding, margin, width, height, and gap. One step equals 0.25rem (4px).
  • w-full is relative to the parent; w-screen is relative to the full viewport.
  • A border needs a base border or width class before a color class has any visible effect.
  • Arbitrary values (w-[350px]) cover exact, one-off measurements outside the standard scale.
