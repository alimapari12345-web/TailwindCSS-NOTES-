1Breakpoint Prefixes

A breakpoint prefix makes a utility class apply only once the browser viewport reaches a certain width. Tailwind ships five default breakpoints.

<img class="w-16 md:w-32 lg:w-48" src="...">

Width is 16 (spacing scale) by default, becomes 32 once the screen is 768px or wider, and becomes 48 once it's 1024px or wider.

2The Mobile-First Mindset

Tailwind's breakpoints are minimum-width based. An unprefixed class applies to every screen size, starting from the smallest. A prefixed class overrides it only from that breakpoint upward.

This means the base (unprefixed) styles should always be written for mobile first, then adjusted upward for larger screens using prefixes. Writing desktop-first and trying to prefix downward goes against how the system is built, and is a common source of confusion when adapting old habits from other frameworks.
<p class="text-sm md:text-base lg:text-lg">
  Small on mobile, base size from tablets up, large from laptops up
</p>
  1. Start by styling the element as it should look on the smallest screen, with no prefix.
  2. Add sm:, md:, etc. only for the properties that need to change at larger sizes.
  3. A property left unprefixed at a given breakpoint simply continues using whatever was last defined at a smaller breakpoint.

3Practical Responsive Patterns

Stacking on mobile, row on desktop

<div class="flex flex-col md:flex-row gap-4">
  <div class="bg-slate-800 p-4">One</div>
  <div class="bg-slate-800 p-4">Two</div>
</div>

Column layout by default (mobile), switching to a row once the screen is medium-sized or larger.

Single column on mobile, grid on desktop

<div class="grid grid-cols-1 md:grid-cols-3 gap-4">
  ...
</div>

One column by default, three columns from md: upward. This is the standard way a card grid collapses gracefully on small screens.

Hiding or showing elements at a breakpoint

ClassEffect
hidden md:blockHidden on mobile, visible from md: upward
md:hiddenVisible on mobile, hidden from md: upward

4Combining with Earlier Modules

Breakpoint prefixes work on any utility from any earlier module, spacing, color, typography, flex, and grid all support the same prefix pattern.

<div class="p-4 sm:p-6 md:p-8 lg:p-12 bg-slate-900 rounded-lg">
  Padding grows at each step up
</div>
Good to know: a max-* variant also exists for the reverse direction, for example max-md:hidden applies only below the md breakpoint, the opposite of md:hidden. This is useful for targeting a narrow range together with a normal breakpoint, such as md:max-lg:block to apply only between md and lg. Not essential for early responsive work, but worth recognizing if seen in other code.

?Common Questions & Misconceptions

Mythmd: means "only on medium screens," similar to a fixed range.
Incorrect. md: means 768px and wider, with no upper limit. Unless overridden by a larger breakpoint like lg: or xl:, an md: style keeps applying all the way up to the largest possible screen.
Q&ADo I need to repeat every property at every breakpoint?
No. Only the properties that actually need to change at a given size need a prefixed class. Anything not overridden continues using the value from the last breakpoint where it was set, cascading upward.
MythPrefixed classes should be written for desktop first, then adjusted down for mobile.
This goes against how Tailwind's breakpoints work. Unprefixed classes are the mobile/base style, and prefixes only add changes going upward from there. Attempting to write desktop-first and prefix downward does not match the min-width system and leads to layouts that don't behave as expected on small screens.
Q&AWhat happens below the sm: breakpoint, is there a class for that?
There is no prefix for "below sm." The unprefixed, base classes already cover everything below the smallest breakpoint, that is the entire purpose of writing base styles without a prefix in the first place.
MythBreakpoints only work with flex and grid layout classes.
Any utility class in the framework can take a breakpoint prefix, colors, font size, padding, border radius, and even less obvious properties like letter spacing can all change at a breakpoint.

✓Summary

  • Five default breakpoints: sm (640px), md (768px), lg (1024px), xl (1280px), 2xl (1536px).
  • Breakpoints are minimum-width based, a prefixed class applies from that width upward, with no built-in upper limit.
  • Unprefixed classes are the mobile/base style and apply to every screen size unless overridden.
  • Write base styles for mobile first, then add prefixes only for what needs to change at larger sizes.
  • Any utility class from any module can take a breakpoint prefix.
  • max-* variants exist for targeting below a breakpoint or a specific range.
